# 文档格式

依据《量潮科技文档格式章程》（量潮科技工作章程·文档格式，官网 https://quanttide.github.io/quanttide-bylaw-of-business-entity/docs/format/ ）执行。本章程适用于所有以 Markdown 编写的正式文档，包括 Git 仓库文档、飞书文档、内部 Wiki。

## 用途

按章程撰写和修订 Markdown 文档，使文档在外观和结构上保持一致，降低阅读成本，消除因格式混乱导致的信息损耗。AI 写作时是格式执行工具而非格式决策者，提交前须检查并清除 AI 常见的格式过度行为。

## 触发

用户编写、修改正式 Markdown 文档时；用户要求按格式章程输出或自查时；文档提交前需要格式检查时。

## 核心原则

格式克制，四字方针：

- 删：删除不必要的格式元素，优先使用段落和标题组织内容。
- 简：能用列表即不使用表格，能用文字即不使用列表。
- 少：全文格式元素的数量控制在必要的最小范围内。
- 一：同一概念全程使用相同名称，不得混用不同术语。

以下行为构成格式过度，必须避免：

- 滥用分隔线装饰章节间隔。
- 任何内容均以列表或表格形式组织。
- 使用「非常」「简单的」「显而易见的」等冗余修饰词。

## 结构规范

- 标题最多使用三级（#、##、###），不得继续嵌套更深层级。
- 一级标题仅文档主标题使用一次，全文不得出现第二个一级标题。
- 标题应简洁，避免在标题中使用标点符号。
- 标题与正文之间、章节之间应以空行分隔。
- 中文文档标题使用中文书写；英文文档标题使用句子大小写（Sentence case）。
- 优先使用空行加标题区分章节，而非分隔线。
- 分隔线仅用于重大的划分节点，全文不得超过三处；可用于文档顶部元信息与正文之间，不得作为装饰。

## 排版要素

### 列表

- 无序列表使用 `-` 作为标记，适用于并列要点与短小条目。
- 有序列表使用 `1.` 作为标记，适用于有明确顺序的步骤。
- 列表项以分号结尾或使用完整句，全文保持风格一致（推荐统一完整句）。
- 列表项不应过长，超过两行应改用段落。
- 嵌套层级不得超过两级，缩进使用两个空格。
- 仅在描述单一事物时、列表项内容超过两行时、内容存在逻辑承接关系时，不得使用列表代替正文。

### 代码块

- 代码块必须标注代码语言类型，以便语法高亮。
- 行内代码使用反引号包裹。

### 表格

- 表格仅用于呈现多维度、需对比的数据。
- 表头应加粗，列对齐使用冒号（:--、:--:、--:）。
- 单元格内容应简洁，避免过长。
- 以下场景不得使用表格：仅为简单的名称-定义对应关系（改用列表）、两列且无对比需求、单元格内容需用完整句子表达。

### 链接

- 外部链接使用标准格式：[链接文本](https://example.com)。
- 内部链接使用相对路径：[文档](./docs/guide.md)。

### 加粗

- 加粗仅用于首次定义关键术语、强调重要操作或警告、引导注意力到关键信息。
- 不得对普通名词或所有术语名词进行加粗。
- 不得连续多个加粗。
- 不得在列表项内部使用加粗。

### 块引用与引号

- 块引用（>）用于标注重要提示或引用内容，不得作为正文的替代格式。
- 引号用于直接引用他人话语、首次定义术语时标记、强调词汇的特殊含义、标注界面元素名称。
- 中文文档使用直角引号「」，英文文档使用双引号（"）。
- 不得对普通名词加引号，不得在列表项或标题中频繁使用引号，不得用引号包裹整个句子（改用块引用）。

## 执行步骤

1. 检查全文仅一个一级标题，无四级及以上标题。
2. 检查标题无标点，章节间有空行。
3. 检查分隔线不超过三处，无装饰性分隔线。
4. 检查列表标记统一，列表项均为完整句，无超过两行的列表项。
5. 检查无名称-定义类的两列表格；表格仅用于多维对比数据。
6. 检查所有代码块标注语言类型。
7. 检查加粗仅用于首次定义术语或关键警告，列表项内无加粗。
8. 检查中文引号均为「」，无弯引号残留。
9. 检查无「非常」「简单的」「显而易见的」等冗余修饰词。
10. 检查同一概念全文术语一致。

## 注意事项

- 允许将本章程全文作为提示词提供给 AI，要求其按照本章程输出格式。
- 已存在的文档与本章程不一致的，应逐步修订以符合本章程的要求。
- 章程各项条文不得被解释为禁止一切格式使用，亦不得被解释为鼓励不经思考的格式滥用。
